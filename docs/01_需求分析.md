# 1 需求分析

## 1.1 项目背景与目标

本项目设计并实现一个基于分布式数据库的学生选课系统，提供选课、退课、课表查询和课程名额查询，并展示查询执行路径与事务恢复过程。

系统以ACID为事务设计原则，采用Python、SQLite和TCP Socket，先在一台计算机上运行三个独立数据站点及一个协调器进程，协调器提供网页和CLI两种入口。各站点分别管理独立的数据库文件，通过网络消息协作，支持部署到不同主机。

默认初始化10000名学生、1000门课程，每名学生生成5条选课记录，共50000条。三个数据站点用于实现水平分片、站点依赖、小表复制、本地连接以及跨站点事务。

系统采用固定业务接口、静态分片和串行请求处理，通过持久化事务状态与日志支持进程重启后的业务恢复。

## 1.2 用户与业务范围

学生通过网页登录后查询课程、选课和退课，学生ID由登录会话确定。管理员查询指定学生课表、课程名单、课程余量、操作记录与系统状态，并执行事务恢复。CLI用于本机调试和故障演示。学生信息和课程目录由初始化程序统一导入。

| 功能编号 | 功能 | 输入 | 成功结果 |
| --- | --- | --- | --- |
| F01 | 查询学生信息 | 学生ID | 返回学生姓名与院系 |
| F02 | 查询课程目录 | 可选课程ID | 返回课程名称及学分 |
| F03 | 查询学生课表 | 学生ID | 返回课程ID、名称、学分及选课时间 |
| F04 | 查询课程名额 | 课程ID | 返回权威站点的容量与剩余名额 |
| F05 | 选课 | 请求ID、学生ID、课程ID | 新增选课记录，剩余名额减一 |
| F06 | 退课 | 请求ID、学生ID、课程ID | 删除选课记录，剩余名额加一 |
| F07 | 查询业务请求状态 | 请求ID | 返回处理中、成功或已中止 |
| F08 | 查询站点与恢复状态 | 管理员会话 | 返回站点可达性及系统是否允许业务访问 |
| F09 | 查询课程选课名单 | 管理员会话、课程ID | 汇总三个学生分片中的学生信息与选课时间 |
| F10 | 查询操作记录 | 管理员会话 | 返回最近100笔事务的操作者、学生、课程及状态 |

F08提供运行状态与恢复进度，供操作者诊断。课程目录按主键或分页查询，每页最多100条。

## 1.3 业务规则与数据约束

学生ID与课程ID均为正整数。同一学生对同一课程最多保留一条有效选课记录。选课必须满足学生存在、课程存在、尚未选修且剩余名额大于零；退课必须满足选课记录存在。退课记录不存在时返回NOT_ENROLLED，并保持名额原值。

每门课程的名额由唯一权威站点维护。静态课程目录保存课程ID、名称与学分，容量和剩余名额存入CourseStock。课程容量在初始化时设定，业务期间保持固定。

对每门课程c，在没有未完成事务且系统处于READY状态时，应满足：

```text
0 <= remaining(c) <= capacity(c)
capacity(c) - remaining(c) = 各学生站点中课程c的有效选课记录数之和
```

协调器统一受理业务读写。在跨站点事务执行期间关闭业务访问入口，待各参与者完成后返回结果并开放入口。

## 1.4 选课与退课流程

选课时，客户端校验参数并携带唯一请求ID提交业务。协调器计算学生站点与课程名额站点，将新增选课记录和扣减名额组织为一个全局事务。所有参与者完成持久化准备后，协调器记录全局决定并通知各站点执行。全部参与者确认完成后，向用户返回成功。

网页退课先由学生确认课程名称和编号。退课事务的本地操作为删除选课记录和增加名额。两个操作位于同一站点时，沿用统一的全局状态流程。

响应丢失后，客户端通过原请求ID查询状态或重试。相同请求ID与参数返回原事务进度或结果；请求ID对应的参数发生变化时，返回REQUEST_CONFLICT。

## 1.5 运行与一致性要求

系统运行一个协调器实例，使用本机独占锁保护身份与日志目录。网页服务或CLI与协调器位于同一进程，业务请求串行执行，任一时刻最多存在一个未决写事务。该事务完成后再受理下一个业务请求。站点顺序处理网络请求。

协调器启动后先恢复日志，再接纳业务。恢复期间系统处于RECOVERING；日志异常或未决事务因参与者失联而无法收敛时进入BLOCKED，管理员可查看状态并重试恢复。系统处于READY时，静态目录与单个学生课表按路由访问对应站点；目标站点不可达时返回NODE_UNAVAILABLE。

网络中断后，协调器根据已持久化的事务阶段执行中止或提交恢复。进程重启后，系统读取日志与事务状态，继续处理未完成的全局决定。

## 1.6 设计内容

第1至6章规定需求、架构、数据分布、查询、通信及事务恢复；第7至9章说明运行演示、验证结果与网页操作。
