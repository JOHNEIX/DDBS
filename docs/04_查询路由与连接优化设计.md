# 4 查询路由与连接优化设计

## 4.1 查询处理流程

选课系统的数据访问模块接收业务操作与结构化参数，依据操作类型、学生ID和课程ID定位站点。站点执行对应查询，并将结果返回协调器。

| 查询 | 路由规则 | 访问站点 |
| --- | --- | --- |
| 学生信息 | student_id mod 3 | 一个学生站点 |
| 学生课表 | student_id mod 3 | 一个学生站点 |
| 静态课程目录 | 固定优先站点0，失败后尝试有效副本 | 一个可用目录站点 |
| 课程剩余名额 | course_id mod 3 | 唯一名额站点 |
| 集群状态 | 遍历固定站点配置 | 三个站点，分别返回状态 |
| 课程选课名单 | 向三个学生分片发送课程筛选查询 | 三个学生站点，按学生编号合并 |

课程目录查询可在已校验版本的副本之间切换。学生信息、课表与课程名额由所属站点返回；访问失败时返回对应站点错误。

## 4.2 本地等值连接

课表查询在学生站点执行，连接条件为Enrollment.course_id=CourseCatalog.course_id。学生姓名从同站点Student读取，结果按course_id排序。输出字段为学生ID、姓名、课程ID、课程名称、学分和选课时间。

逻辑查询如下，参数必须使用SQLite占位符绑定：

```sql
SELECT s.student_id, s.name, c.course_id,
       c.course_name, c.credits, e.enrolled_at
FROM Student AS s
JOIN Enrollment AS e ON s.student_id = e.student_id
JOIN CourseCatalog AS c ON e.course_id = c.course_id
WHERE s.student_id = ?
ORDER BY c.course_id;
```

查询采用等值内连接，由站点内的SQLite执行。SQLite依据表结构与索引选择访问路径。[1]

## 4.3 查询优化依据

首先按学生ID定位站点，再按学生ID筛选选课记录，最后在该站点连接完整课程目录。学生、选课记录和课程目录共同放置，使课表连接在所属站点完成。站点在本地完成筛选与连接，只向协调器返回最终课表。

这一设计通过数据放置、选择下推、投影下推和本地连接减少查询过程中的数据传输。1000条课程目录在初始化时复制到三个站点，业务期间按只读方式访问。

## 4.4 连接语义与数据放置

课表查询所需的课程目录位于学生站点，查询直接执行本地等值连接。

关系代数中，笛卡尔积后按连接条件选择可以改写成条件连接。自然连接按共同属性匹配，并合并重复的连接列。本系统通过JOIN ON显式指定student_id和course_id连接条件。[1]

Student与Enrollment采用相同的分片键和映射，满足可连接元组位于同一站点的放置条件。CourseCatalog在各学生站点保留完整副本，为课程信息连接提供本地数据。

## 4.5 多站点处理与结果语义

集群状态查询由协调器汇总。协调器显示当前系统运行状态，并依次访问三个站点，显示各站点的可达性、站点编号、数据集版本和课程目录摘要。

## 4.6 查询可见性与错误处理

协调器在READY状态下接纳业务查询。业务请求通过同一把协调器锁串行执行；RECOVERING与BLOCKED期间返回对应状态错误，恢复完成后重新开放入口，使业务查询读取完整的事务结果。

只读请求超时可以按原参数重试，课程目录可尝试其他已校验副本；涉及权威分片的查询只能访问原站点。站点按接口约定返回所需字段和记录。

参考资料：[1] [关系连接语义](https://www.postgresql.org/docs/current/queries-table-expressions.html)。

## 4.7 跨站点课程名单

GET_ROSTER按课程ID向三个学生分片发送查询。每个站点在Enrollment上按课程筛选，并与本地Student连接，返回学生编号、姓名、院系和选课时间。协调器按学生编号合并，单次最多返回100条；after_id用于继续读取后续学生。管理员页面显示课程选课名单，执行轨迹记录三个目标站点。
