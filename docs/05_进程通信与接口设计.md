# 5 进程通信与接口设计

## 5.1 通信模型

协调器作为TCP客户端，数据站点作为TCP服务器。使用AF_INET与SOCK_STREAM，同一协议既用于127.0.0.1上的本机进程，也用于局域网内的不同主机。每次连接承载一个请求和一个响应，完成后关闭。

协调器顺序请求各参与者，站点顺序接受并处理连接，通信关系为协调器发起请求、站点返回响应。恢复时，协调器调用TX_STATUS并重发事务决定。

TCP按字节流传输数据。发送端使用sendall，接收端通过recv_exact(n)循环读取指定长度；接收到空字节时按连接关闭处理。[1]

## 5.2 消息封装与超时

```text
消息 = 4字节无符号大端正文长度 + 对应长度的UTF-8 JSON正文
长度取JSON正文经UTF-8编码后的字节数
```

正文长度范围为1至1048576字节。长度为0、超限、正文截断、UTF-8非法或JSON格式错误时，站点拒绝该消息并关闭连接；能够构造合法响应时返回协议错误。请求字段白名单校验后才进入业务处理。

连接超时设为3秒，一次完整收发的绝对截止时间设为10秒。每次recv使用剩余时间作为超时参数。

网络异常后最多自动重试2次，间隔0.5秒；随后转入状态查询或恢复流程。重试沿用原事务ID和已持久化的全局决定。

## 5.3 标识与请求格式

业务请求ID request_id由CLI或网页生成并保留，标识一次选课或退课。全局事务ID tx_id由协调器为首次接纳的写请求生成，并与request_id建立持久化映射。rpc_id标识一次消息调用；同一次网络重试沿用原rpc_id，不同阶段使用不同rpc_id。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| version | 整数 | 协议版本，固定为1 |
| cluster_id | 字符串 | 集群标识，必须匹配站点配置 |
| coordinator_id | 字符串 | 固定协调器身份，重启后保持不变 |
| rpc_id | 字符串 | 本次消息调用标识 |
| op | 字符串 | 白名单操作名称 |
| tx_id | 字符串或null | 事务操作必填，普通只读请求为null |
| payload | 对象 | 操作参数与必要业务请求ID |

请求示例：

```json
{"version":1,"cluster_id":"minishard-demo",
 "coordinator_id":"coord-1","rpc_id":"rpc-example-01",
 "op":"GET_SCHEDULE","tx_id":null,
 "payload":{"student_id":1001}}
```

响应保留version与rpc_id，包含ok、code、message和data。成功时ok=true且code=OK；失败时ok=false且code为明确错误码。事务响应在data中返回state，区分PREPARED、COMMITTED与ABORTED。

```json
{"version":1,"rpc_id":"rpc-example-01","ok":true,
 "code":"OK","message":"success",
 "data":{"student":{"student_id":1001,
 "name":"学生01001","department":"院系2"},
 "courses":[],"query_plan":[]}}
```

## 5.4 站点接口

| 接口 | 主要参数 | 结果或行为 |
| --- | --- | --- |
| PING | 无 | 站点编号、数据集版本、目录摘要 |
| GET_STUDENT | student_id | 学生信息或不存在 |
| GET_CATALOG | course_id或after_id、limit | 单门课程或分页目录 |
| GET_SCHEDULE | student_id | 本地连接后的课表 |
| GET_STOCK | course_id | 权威容量与剩余名额 |
| GET_ROSTER | course_id、after_id | 当前学生分片内的课程选课名单，最多100条 |
| PREPARE | tx_id、request_id、payload_digest、operations | PREPARED或拒绝原因 |
| COMMIT | tx_id | COMMITTED或状态冲突 |
| ABORT | tx_id | ABORTED或状态冲突 |
| TX_STATUS | tx_id或list_unfinished=true | 单事务状态或未完成事务列表 |

GET_CATALOG的limit范围为1至100，默认100，结果按course_id升序，after_id表示上一页最后一个ID。学生、选课和名额请求均校验本地归属，路由错误时返回WRONG_NODE。

PREPARE的operations只允许ENROLL_ADD、ENROLL_REMOVE、STOCK_DEC、STOCK_INC。每项操作带seq、所需ID，新增选课携带协调器生成的enrolled_at，重试沿用该值。参与者核对操作摘要后执行对应的预定义SQL。

## 5.5 幂等规则与错误码

| 情况或错误码 | 处理方式 |
| --- | --- |
| INVALID_ARGUMENT / PROTOCOL_ERROR | 返回错误原因，等待修正请求 |
| WRONG_NODE / VERSION_MISMATCH | 检查路由、集群与数据集配置 |
| NOT_FOUND / ALREADY_ENROLLED / NOT_ENROLLED / NO_SEATS | 业务拒绝，协调器决定ABORT |
| LOCK_CONFLICT / NODE_UNAVAILABLE | 准备阶段决定中止；决定后的故障保留原决定并恢复 |
| TX_CONFLICT / REQUEST_CONFLICT | 标识被不同参数复用，拒绝执行 |
| TX_UNKNOWN | 返回未知事务状态，协调器核对日志 |
| RECOVERING / BLOCKED | 暂停业务，先完成恢复 |

PREPARE核对原操作摘要，重复请求返回已有状态。重复COMMIT与ABORT返回对应终态。未知事务收到ABORT时写入ABORTED墓碑记录，后续PREPARE返回该终态；收到COMMIT时返回TX_UNKNOWN。终态事务收到相反决定时返回TX_CONFLICT。

CLI的选课、退课、课表、名额与业务状态命令直接调用同进程协调器的业务函数。请求ID与tx_id的业务状态查询由协调器全局日志提供，站点TX_STATUS查询本地参与者状态。

## 5.6 SQL与时间格式

业务参数通过SQLite参数绑定进入SQL。所有业务时间采用UTC ISO 8601格式，如2026-11-19T08:00:00Z，显示时可转换为用户本地时间；恢复顺序由日志seq和事务状态确定。

参考资料：[1] [Python socket接口](https://docs.python.org/3/library/socket.html)及[Socket编程说明](https://docs.python.org/3/howto/sockets.html)。

## 5.7 网页身份与权限

浏览器先获取/api/session的请求令牌，再通过/api/login建立HttpOnly会话Cookie。学生ID从服务端会话读取；管理员调用/api/roster、/api/records、/api/status和/api/recover。POST请求携带X-Session-Token并校验来源。HTTP接口与角色表见09网页客户端设计与操作。
