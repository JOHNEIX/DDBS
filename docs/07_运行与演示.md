# 7 运行与演示

本项目设计并实现一个基于分布式数据库的学生选课系统，提供选课、退课、课表查询和课程名额查询，并展示查询执行路径与事务恢复过程。系统采用Python标准库实现，部署为三个数据站点和一个协调器，提供网页客户端与CLI。学生与选课记录共同分片，课程目录全复制，课程名额按课程ID分片。通过TCP Socket、持久化业务意图和应用层2PC协调选退课，支持查询执行追踪与进程故障恢复。

## 快速启动

安装Python 3.10或更新版本，在项目目录执行：

```powershell
python web_server.py --local --open
```

Windows可以双击start_web.bat。首次启动生成10000名学生、1000门课程和50000条初始选课记录，启动三个站点和网页服务，并打开http://127.0.0.1:8081。已经运行的站点会自动复用。

原命令行界面正在运行时，先在其中输入exit，释放协调器。网页服务所在的终端保持运行；结束时按Ctrl+C，关闭本次启动的站点。

网页使用以下演示账号登录：

| 账号 | 密码 | 身份 |
| --- | --- | --- |
| 1001 | student1001 | 学生1001 |
| 1002 | student1002 | 学生1002 |
| admin | admin123 | 管理员 |

学生在“课程列表”按课程编号100查询并选课，在“我的课表”查看结果；退课时确认课程名称和编号。系统依据登录账号确定学生身份。选退课直接执行，先校验选修记录与名额。

管理员可查看课程容量与余量、课程选课名单、指定学生课表和最近100笔操作记录，在“系统管理”查看节点状态并执行事务恢复。“执行过程”展示管理员本次查询的路由与事务阶段。课程名单由三个学生分片汇总。

每次选退课的请求编号自动生成并保留。结果待确认时，页面提供“查询结果”和“重试原请求”。完整操作与接口见09_网页客户端设计与操作.md。

三个站点已独立启动时，也可以执行python web_server.py --open连接现有站点。--host和--port分别配置HTTP监听地址与端口；节点地址仍由config.json配置。

## 命令行操作

执行python main.py --trace local进入命令行，或双击start.bat。终端中依次输入：

```text
status
schedule 1001
stock 100
enroll 1001 100 --request demo-add
schedule 1001
history demo-add
drop 1001 100 --request demo-drop
stock 100
exit
```

查询时显示ROUTE、RPC和LOCAL_JOIN，包括目标站点、传输字节数、结果行数及SQLite真实执行计划。选退课显示STARTED、PREPARED、DECIDED_COMMIT和DONE_COMMIT。exit关闭此次启动的三个站点。

## 独立启动四个进程

先初始化一次：

```powershell
python main.py init
```

在三个终端分别启动站点：

```powershell
python node_server.py --node 0
python node_server.py --node 1
python node_server.py --node 2
```

在第四个终端启动CLI：

```powershell
python main.py --trace shell
```

也可以单次执行命令，例如python main.py --trace schedule 1001。--config、--trace、--json和--fault放在子命令之前；--request放在enroll或drop之后。

## 故障恢复演示

使用独立站点终端演示，执行下面的命令前退出正在运行的网页服务或CLI，释放协调器锁。每次使用新的请求ID与一组尚未选修的学生课程。

### 提交决定已保存后协调器退出

```powershell
python main.py --trace --fault after_decision enroll 1001 100 --request crash-commit
python main.py --trace recover
python main.py history crash-commit
python main.py schedule 1001
```

第一次命令保存提交决定后以退出码77退出。recover读取全局日志，向参与者重发COMMIT，最终状态为DONE_COMMIT。

### 准备完成后协调器退出

```powershell
python main.py --trace --fault after_prepare enroll 1002 101 --request crash-prepare
python main.py --trace recover
python main.py history crash-prepare
```

恢复后状态为DONE_ABORT，准备意图与逻辑锁被清理。

### 部分提交后站点离线

执行python main.py --trace --fault after_first_commit enroll 1003 102 --request crash-partial后，先停止课程站点0，再执行python main.py --trace recover。系统显示BLOCKED，request crash-partial显示处理中。重启站点0，再次recover，事务收敛为DONE_COMMIT。

### 站点提交后响应丢失

先关闭原站点1，以python node_server.py --node 1 --fault after_commit启动站点1，再从CLI执行enroll 1001 103 --request lost-response。站点在本地提交后以退出码78退出，协调器显示BLOCKED。普通方式重启站点1后，执行python main.py --trace recover，站点返回原COMMITTED状态，名额保留首次扣减结果。

站点还支持--fault after_prepare，模拟持久化准备完成但响应丢失。--fault仅影响指定启动的进程，普通方式重启后恢复正常。

## 状态与持久化

系统状态为STARTING、RECOVERING、READY、BUSY、BLOCKED；每笔全局事务使用STARTED、DECIDED_COMMIT或DECIDED_ABORT、DONE_COMMIT或DONE_ABORT。普通查询访问离线站点时返回NODE_UNAVAILABLE，系统回到READY。未决事务因参与者离线而无法收敛时进入BLOCKED，recover完成后回到READY。

status把协调器本地系统状态与站点PING信息合并显示。request查询业务结果，history展示该请求的全局日志事件。诊断轨迹保存在data/coordinator/trace.jsonl，全局事务决定及操作者保存在global.jsonl，账号与密码摘要保存在accounts.json，登录会话在重启后重新建立；各站点的本地事务状态、意图与锁保存在自己的node.db。

## 多机与Tailscale

先在一台电脑初始化集群，将各站点对应的data/nodeN目录分发到相应电脑。协调器电脑保留data/coordinator。每台电脑使用相同集群标识、协调器标识、数据集版本和站点映射，修改config.json中host为各电脑可达的局域网或Tailscale IP。每个站点监听自己的host，也可通过bind_host单独指定本地监听地址。

分别运行对应node_server.py，再在协调器电脑执行shell。防火墙与Tailscale访问规则放行协调器到三个TCP端口。单机默认端口为9100、9101、9102。

```powershell
python -m unittest discover -s tests -v
```

26项验证使用独立临时数据库和随机空闲端口，覆盖选退课、跨站点名单、登录权限、请求幂等、逻辑锁、节点离线、报文拆分、日志异常及真实进程崩溃恢复。

## 更新与重新启动

更新程序后，先退出网页服务和三个数据站点，再执行python web_server.py --local --open，并在浏览器按Ctrl+F5刷新。独立启动的站点在各自终端按Ctrl+C关闭。网页的--local会复用已运行的站点，因此更新站点代码后需要一并重启站点。
