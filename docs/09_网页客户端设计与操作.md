# 9 网页客户端设计与操作

## 9.1 结构

浏览器通过HTTP访问web_server.py，网页服务与协调器运行在同一进程，协调器通过TCP Socket访问三个SQLite站点。网页与CLI复用Coordinator的分片路由、本地连接、持久化意图和两阶段事务恢复。

```text
浏览器 → HTTP与登录会话 → 网页服务与协调器 → TCP Socket → 站点0、1、2
```

auth.py保存账号与密码摘要，维护8小时登录会话；web_server.py集中校验身份与权限；web目录维护页面、样式和交互。业务通过协调器的gate锁串行执行。界面采用黑白灰，主要内容为导航、查询栏与数据表。

## 9.2 启动与账号

执行python web_server.py --local --open，或双击start_web.bat，访问http://127.0.0.1:8081。启动器复用已运行站点并启动缺少的站点，退出时关闭此次创建的站点。切换网页与CLI时先退出原协调器入口。

| 账号 | 密码 | 身份 |
| --- | --- | --- |
| 1001 | student1001 | 学生1001 |
| 1002 | student1002 | 学生1002 |
| admin | admin123 | 管理员 |

首次运行网页服务时自动建立演示账号。账号与加盐PBKDF2密码摘要保存在data/coordinator/accounts.json，进程重启后重新登录。

更新程序后，退出原网页服务及三个数据站点，再执行启动命令，并在浏览器按Ctrl+F5刷新。独立运行的站点在各自终端按Ctrl+C退出。

## 9.3 学生操作

登录学生账号后，“课程列表”每页显示10门课程，支持按课程编号查询。选课成功后在“我的课表”查看课程、学分与选课时间。

学生身份由服务端会话绑定，选退课使用本人学生ID。退课按钮弹出课程名称与编号确认，确认后提交退课事务。选课校验课程存在、尚未选修和剩余名额；退课校验本人选课记录。

每次操作生成请求ID。结果待确认时页面显示“查询结果”和“重试原请求”，两者沿用原请求ID与参数。终态结果返回后刷新课表与名额。

## 9.4 管理员操作

| 入口 | 操作 |
| --- | --- |
| 课程列表 | 查看课程学分、容量与余量，点击“名单”查看选课学生 |
| 学生课表 | 输入学生编号，查询其课程、选课时间与学分合计 |
| 操作记录 | 查看最近100笔事务的时间、操作者、学生、课程、动作和最新状态 |
| 系统管理 | 查看系统状态、节点可达性、数据集版本和待恢复事务数量，执行“继续事务恢复” |
| 执行过程 | 展开查看本次调用的路由、RPC字节、连接计划与事务事件 |

课程名单由协调器访问三个学生分片，每个站点筛选Enrollment并与本地Student连接，再按学生编号汇总。单次最多返回100条，与初始课程容量100对应。个人课表路由到学生所属站点，在站点内连接Student、Enrollment和CourseCatalog。

课程目录先读取副本，再按课程ID查询名额权威站点。SQL由站点执行预定义语句，业务参数使用占位符绑定。

## 9.5 HTTP接口与权限

| 方法与路径 | 参数与权限 |
| --- | --- |
| GET /api/session | 当前身份和POST请求令牌 |
| POST /api/login | username、password，建立会话 |
| POST /api/logout | 清除当前会话 |
| GET /api/student、/api/schedule | 学生查询本人；管理员传student_id |
| GET /api/catalog | 已登录，after_id分页或course_id精确查询，并汇总名额 |
| GET /api/stock | 已登录，course_id |
| GET /api/request | request_id，学生查询本人请求；管理员可查询全部 |
| POST /api/enroll、/api/drop | 学生，course_id、request_id，身份从会话读取 |
| GET /api/roster | 管理员，course_id及可选after_id |
| GET /api/records | 管理员，最近100笔事务 |
| GET /api/status | 管理员，运行状态、站点信息与未决事务 |
| POST /api/recover | 管理员，依据全局决定继续恢复 |

POST采用JSON正文并携带X-Session-Token，服务端校验来源。登录Cookie设置HttpOnly与SameSite=Strict。业务响应包含ok、data或错误码及system_state，管理员业务响应附带trace。/api/session返回当前身份和请求令牌。学生端展示业务结果，管理端保留折叠的执行轨迹。

## 9.6 验证

自动验证覆盖登录与退出、错误密码、学生身份绑定、管理员权限、操作者审计、三个分片名单汇总、HTTP选退课、原请求重试、部分提交恢复、静态资源响应类型和已运行站点复用。

浏览器实际完成学生登录、选课、取消退课、确认退课、管理员学生课表、课程名单、操作记录与系统管理检查。测试使用独立数据与端口。
